  <action>
Create lib/ftp.ts with the following exports:

1. `getFTPClient()` - Returns a connected FTP client Promise, reusing connection logic from upload/route.ts
2. `getFileFromFTP(relativePath: string): Promise<Buffer>` - Retrieves file from FTP at `${FTP_BASE_PATH}${relativePath}`, returns Buffer, throws on error (not found, connection failed, etc.)
3. `listFilesFromFTP(relativePath: string = ''): Promise<Array<{name: string, path: string, size: number, createdAt: Date}>>` - Lists files recursively from FTP at `${FTP_BASE_PATH}${relativePath}`, returns same structure as local readDirRecursive

Use the existing `ftp` package (already in package.json via upload/route.ts). Read FTP config from process.env: FTP_HOST, FTP_USER, FTP_PASSWORD, FTP_BASE_PATH. All are required (validated in upload/route.ts).

Connection config:
```typescript
{
  host: process.env.FTP_HOST!,
  user: process.env.FTP_USER!,
  password: process.env.FTP_PASSWORD!,
  secure: false,
}
```

For getFileFromFTP: use client.get(remotePath) which returns a readable stream. Collect chunks into Buffer.

For listFilesFromFTP: use client.list(remotePath) to get file entries. Recurse into directories. Match the return shape of readDirRecursive in files/route.ts: {name, path, size, createdAt}.

Handle FTP errors properly - throw descriptive errors that callers can catch for fallback logic.
</action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Application → FTP Server | External FTP service, credentials in env, potential MITM on unencrypted FTP |
| Client → /api/uploads/[...path] | Untrusted path parameter, could traverse directories |
| Client → /api/files | Untrusted query params, could list arbitrary directories |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | lib/ftp.ts getFileFromFTP | mitigate | Validate relativePath contains no '..' or absolute paths; normalize and ensure it stays under FTP_BASE_PATH |
| T-01-02 | Information Disclosure | lib/ftp.ts listFilesFromFTP | mitigate | Same path validation; ensure FTP_BASE_PATH prefix enforced |
| T-01-03 | Spoofing | FTP connection | accept | FTP uses plain auth (credentials in env); MITM risk accepted per current infrastructure (FTPS not configured) |
| T-01-04 | Denial of Service | FTP operations | mitigate | Add connection timeout (10s) and operation timeout (30s); reject oversized files (>100MB) |
| T-01-05 | Elevation of Privilege | FTP client reuse | mitigate | Don't reuse client across requests; create fresh connection per operation to avoid state leakage |

</threat_model>
