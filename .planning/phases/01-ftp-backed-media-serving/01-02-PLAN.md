Modify app/api/uploads/[...path]/route.ts:

1. Add import: `import { getFileFromFTP } from '@/lib/ftp';`

2. In the GET handler, wrap the FTP fetch in try/catch:
   - Construct relativePath from params (join path array with '/')
   - Call `getFileFromFTP(relativePath)` 
   - On success: return fileBuffer with correct Content-Type and Cache-Control

3. In catch block: implement fallback to local filesystem:
   - Check if error is "not found" type (ENOENT) or connection error
   - Construct local filePath: `join(process.cwd(), 'public', 'uploads', ...path)`
   - Use existing `existsSync` and `readFile` logic
   - Return local file with same headers

4. Preserve existing content-type logic (lines 23-29) and Cache-Control header (line 34).

5. Error handling: distinguish between "file not on FTP" (fallback) vs "FTP connection error" (fallback) vs "file not on FTP AND not locally" (return 404).

Key code structure:
```typescript
try {
  const fileBuffer = await getFileFromFTP(relativePath);
  return new NextResponse(fileBuffer, { headers: { 'Content-Type': contentType, 'Cache-Control': 'public, max-age=31536000, immutable' } });
} catch (ftpError) {
  // Fallback to local
  const filePath = join(process.cwd(), 'public', 'uploads', ...path);
  if (!existsSync(filePath)) {
    return new NextResponse('File not found', { status: 404 });
  }
  const fileBuffer = await readFile(filePath);
  return new NextResponse(fileBuffer, { headers: { 'Content-Type': contentType, 'Cache-Control': 'public, max-age=31536000, immutable' } });
}
```

The `relativePath` should be the path array joined with '/', e.g., `path.join('/')`. FTP_BASE_PATH is prepended inside getFileFromFTP.
